## Layout & Screen Contract

Target: iPad landscape (≈1180×820 CSS px, iPadOS 26.5.2) on the music stand, read from ≈60 cm [REQ UI-02]. Laptop browser secondary.

### Global rules (all inherited from Phase 1, still binding)
- Page padding 24px top / 32px left/right + `env(safe-area-inset-*)` [P1].
- **Bottom free zone:** the bottom 96px + `env(safe-area-inset-bottom)` stay empty (`.app` padding already does this) [P1, CTX D-03]. Nothing on this page is pinned to the bottom; no fixed/sticky footer.
- The page may scroll vertically if content is taller than the viewport (e.g. long error steps, narrow widths). The scroll end still keeps the 96px free zone.
- No URL or hash change at any time, including when the mic starts/stops or an error appears [STACK, CTX D-03].
- Minimum touch target 64×64px [P1].

### Screen: Mikrofon-Test (replaces `MicPlaceholderScreen`)

Screen id: rename `'mic-placeholder'` → `'mic-test'` in `appStore.ts` [RES, recommended]. Overview tile "Mikrofon-Test" loses its "kommt bald" badge; title and description stay unchanged [RES].

**Wide layout (viewport width ≥ 1100px, the iPad landscape case) [DISC]:**

CSS grid on the screen root: `grid-template-columns: minmax(0, 3fr) minmax(0, 2fr)`, column gap 32px. At 1180px this gives a left column ≈650px and a right column ≈434px.

```
┌────────────────────────────────────────────┬──────────────────────────────┐

│                                     (24px)  │ Startart ......... Safari-Tab │
│ [ Mikrofon starten ]  Status text (2 lines) │ App-Version ...... …          │
│                                     (24px)  │ Audio-Status ..... …          │
│ (optional MicHinweis box, then 24px)        │ Abtastrate App ... …          │
│ ┌ Messkarte ─────────────────────────────┐  │ …                             │
│ │  A4          +3 Cent                   │  │ (16 rows, see DiagnosePanel)  │
│ │  (120px)     440,3 Hz                  │  │                               │
│ │              international: A4        │  │                               │
│ │  [−50 ···· ▒▒▒│▒▒▒ ···· +50] tuner     │  │                               │
│ │  Lautstärke −32 dB   Erkennungss. 0,97 │  │                               │
│ │  [██████|░░░░░]      [█████████|░]     │  │                               │
│ └────────────────────────────────────────┘  │                               │
└────────────────────────────────────────────┴──────────────────────────────┘
                (bottom 96px free zone – background only)
```

- **Left column**, top to bottom:
  1. Header row (existing `.screen-header--unterseite`): `BackButton` (64px high, min-width 160px) top-left, `<h1>` "Mikrofon-Test" 24px to its right [P1].
  2. 24px gap (exception, see Spacing: this page is dense; Phase 1 used 48px for a single paragraph).
  3. **Control row:** `MicToggleButton` on the left, `MicStatusText` 24px to its right, vertically centered on the button, max 2 lines.
  4. 24px gap.
  5. *(only when a hint is active)* `MicHinweis` box, then 24px gap.
  6. **Content slot:** exactly one of:
     - `Messkarte` (measurement card) in states idle / starting / running / stopped,
     - `MicFehler` box in the error states,
     - `WarningBar` [P1] in the insecure state.
- **Right column:** `DiagnosePanel`, starting at the very top of the page (aligned with the header row, `align-self: start`), so one landscape screenshot shows live values and all diagnostics together [DISC: there is no Mac for remote debugging, screenshots are the debugging tool].

Height budget at 820px (usable 700px after 24px top padding and 96px free zone): header 64 + 24 + control row 96 + 24 + Messkarte ≈360 = **≈568px** (fits without scrolling); DiagnosePanel ≈670px (fits).

**Narrow layout (< 1100px, e.g. iPad portrait, small laptop windows):** single column in this order: header row, control row, hint, content slot, 32px gap, DiagnosePanel. Below 600px the control row stacks: button on its own line (full width), status text 16px below.

### Messkarte (measurement card) [DISC, REQ MIC-02, MIC-03]
Surface `--color-surface`, radius 16px, padding 24px. Internal layout:

1. **Note row** (flex, `align-items: center`, gap 32px):
   - `NotenAnzeige`: the note label, e.g. `A4`, at `--font-anzeige` (120px), weight 600, line-height 1.0, tabular nums, `min-width: 4ch` so the row doesn't jump between "C4" and "Gis4".
   - Right of it, a vertical stack (gap 8px):
     - Cents value at Heading size (32px/600), e.g. `+3 Cent`.
     - Frequency at Body size (24px/400, text secondary), e.g. `440,3 Hz`.
     - International name at Label size (20px/400, text secondary), e.g. `international: A4` (resolves the German B/H ambiguity [RES A5]).
2. 24px gap.
3. **Tuner bar** (`CentAnzeige`), full card width:
   - Track: 48px high, radius 8px, fill `--color-bg`.
   - ±10-cent band: centered rectangle from −10 to +10 (20% of width), full height, fill `--color-meter-band`. It is the visual check for the A4 criterion [CTX D-08].
   - Center line at 0: 2px wide, full height, `--color-text`.
   - Needle: 8px wide, full height (48px), radius 4px, `--color-accent`, positioned at `left: (cents + 50) / 100 × width` (center of needle), clamped to the track. Hidden when no note is shown.
   - Scale labels 8px below the track, Label size (20px), text secondary, centered under their positions: `−50` (0%), `−10` (40%), `0` (50%), `+10` (60%), `+50` (100%; the outer labels align to the track edges instead of centering).
4. 24px gap.
5. **Meter row**: two `PegelBalken` side by side (CSS grid `1fr 1fr`, gap 24px; stacked with 16px gap below 600px):
   - Label line (Label size 20px): name left in text secondary, value right in text primary, tabular nums.
   - 8px gap, then the bar: 24px high, radius 12px, track `--color-bg`, fill `--color-text-secondary`, width = normalized value.
   - Threshold marker: 2px wide vertical line, full bar height + 4px above and below (32px total), `--color-text`, at the gate/threshold value.
   - **Lautstärke** (level): range −90 dB … 0 dB (linear in dB), marker at `GATE_OPEN_DB` (−60 dB).
   - **Erkennungssicherheit** (clarity): range 0 … 1, marker at `CLARITY_MIN` (0,90). Shows the raw pitchy clarity, also when the note is rejected [RES].
   - Both bars use `role="meter"` with `aria-valuemin/max/now` and `aria-valuetext` (e.g. "−32 dB", "0,97").

### Messkarte display states
| Situation | Note | Cents / Hz / international | Needle | Bars |
|-----------|------|---------------------------|--------|------|
| idle, starting, stopped | `–` in `--color-text-muted` | `– Cent`, `– Hz`, `international: –` (all text muted) | hidden | empty (no fill), values `–` |
| running, no valid note | `–` in `--color-text-muted` | `– Cent`, `– Hz`, `international: –` | hidden | live |
| running, note detected | e.g. `A4` in `--color-text` | live values | visible, live | live |
| running, hold time (≤ `HOLD_MS` 400ms after the gate closed) | last note in `--color-text-secondary` (dimmed) | last values, text secondary | visible but at 50% opacity | live |

The card is always rendered in the non-error states, so starting the mic never shifts the layout [DISC].

### Update rate & motion
- UI values are published at ≈15 Hz (analysis still runs every frame) [RES].
- Needle: `transition: left 66ms linear`. Bars: `transition: width 66ms linear`. Note text: instant swap, no animation.
- `@media (prefers-reduced-motion: reduce)`: no transitions at all.
- No pulsing/blinking elements anywhere on this page (the iOS mic indicator already shows the mic is live) [DISC].

### MicToggleButton [CTX D-01, D-02]
One button, always at the same position, whose label and style follow the state:

| State | Label | Style | Action |
|-------|-------|-------|--------|
| idle / stopped | Mikrofon starten | accent fill, `--color-text-on-accent` (like Phase 1 Start) | `start()` |
| starting | Startet … | `disabled`, fill `--color-accent-pressed`, no press effect | – |
| running | Mikrofon stoppen | `--color-surface` fill, `--color-text` label, pressed `--color-surface-pressed` | `stop()` |
| error (verweigert / keinMikrofon / belegt / unbekannt) | Nochmal versuchen | accent fill (same as "Mikrofon starten") | `start()` |
| insecure (`isSecureContext === false` or no `navigator.mediaDevices`) | – | **not rendered**; the WarningBar takes the content slot and the status text explains | – |

Size: height 96px, `min-width: 320px`, horizontal padding 32px (the label never wraps; "Nochmal versuchen" makes the button wider than 320px), radius 16px, Heading size 32px/600. Pressed / focus / hover / reduced-motion behaviour exactly as `.btn-start` [P1]. The tap handler must create/resume the AudioContext synchronously before any `await` [CTX D-01, RES Pattern 1]. Focus stays on the button when its label changes.

### MicHinweis (non-fatal hint box) [DISC, RES Pattern 6]
Shown between control row and Messkarte, only while the condition holds. Visual: like `WarningBar` but max-width = column width, padding 16px, 4px left border `--color-warning`, background `--color-warning-surface`, Body 24px, `role="status"` `aria-live="polite"`. Never more than one hint at a time (priority: keinSignal > angehalten > hintergrund).

### MicFehler (error box) [DISC, CTX Claude's discretion]
Replaces the Messkarte in error states. Visual: same box style as `WarningBar` [P1] (padding 24px, radius 12px, 4px left border `--color-warning`, `--color-warning-surface`), full column width, `role="alert"`.
- Title: Body size 24px, weight 600.
- 8px gap, intro sentence: Body 24px/400.
- 16px gap, ordered list (`<ol>`) of steps, Body 24px/400, 8px between items, list padding-left 32px.
- No button inside the box: the retry action is the MicToggleButton above ("Nochmal versuchen"), so there is one primary action at one fixed position.
- Error details (`err.name: err.message`) are **not** shown in the box; they appear in the DiagnosePanel row "Fehlerdetails".

### DiagnosePanel [DISC, REQ MIC-04, RES Pattern 6]
- Always visible, never collapsible (screenshots must show everything) [RES].
- Surface `--color-surface`, radius 16px, padding 24px.
- `<h2>` "Diagnose", Heading 32px/600, line-height 1.2, then 16px gap.
- `<dl>` as CSS grid: `grid-template-columns: max-content minmax(0, 1fr)`, column gap 16px, row gap 4px. All text Label size 20px, line-height 1.4. `<dt>` in text secondary, `<dd>` in text primary, tabular nums, `overflow-wrap: anywhere` (long mic labels and error messages wrap instead of widening the panel).
- **Problem values** use `--color-warning-text` **and** always carry a text marker (`✗`, `AN`, `≠`, or the word itself), never color alone.
- Rows are rendered in every state. Before the mic has run, values that need the mic show `–`. Values update live while running; "Analysen/Sek." updates once per second.

## Typography

This screen uses **exactly 4 sizes and 2 weights**. Phase 1's Display (56px) token stays in `tokens.css` for the welcome screen but is **not used on this page**. One new token is added: `--font-anzeige: 120px` [RES Pattern 4 asked the UI-SPEC to declare it].

| Role | Size | Weight | Line Height | Used for on this page |
|------|------|--------|-------------|-----------------------|
| Label | 20px | 400 | 1.4 | All DiagnosePanel rows, meter labels and values, tuner scale labels, international note name |
| Body | 24px | 400 / 600 | 1.5 | Status text, frequency line, MicHinweis, error intro and steps (400); error title (600) |
| Heading | 32px | 600 | 1.2 | `<h1>` "Mikrofon-Test", `<h2>` "Diagnose", cents value, button labels (toggle, Zurück) |
| Anzeige (new) | 120px | 600 | 1.0 | The detected note label only (e.g. `A4`, `Gis4`, `–`) |

Weights: 400 and 600 only [P1]. Nothing below 20px [P1]. `tabular-nums` on every live number (note label, cents, Hz, dB, clarity, all diagnostics values).

Why 120px: from ≈60 cm the note must be readable at a glance while both hands are on the keys; 120px cap height ≈ 85px is legible from well beyond 2 m, and "Gis4" (the widest label) still fits next to the cents stack in the ≈600px card [DISC].

| Situation | Behaviour |
|-----------|-----------|
| Screen opens | Focus on `<h1>` (`tabIndex={-1}`) [P1]. Mic is off. Startart and App-Version are already filled. If insecure: WarningBar shown, no toggle |

## Claude's Discretion Decisions (for user review)

The user delegated these ("entscheide du") or did not discuss them:
1. **Note naming:** German names with sharps (Cis, Dis, Fis, Gis), but **B** for B♭ and **H** for B natural; scientific octave (C4 = middle C, A4 = 440 Hz). A small "international: …" line resolves the B/H ambiguity.
2. **Note display:** 120px note label, cents as a number (32px) **plus** a tuner bar from −50 to +50 with a grey ±10-cent band that directly visualises the A4 test criterion (D-08).
3. **Diagnostics:** always visible right-hand panel (no collapsing), 16 rows, top-aligned so one landscape screenshot captures everything. Safari's unreported filters show "nicht gemeldet" without a warning.
4. **Mic errors:** one German box per error kind with numbered steps, including "Safari ganz schließen / iPad neu starten" for the iOS 26.5.2 bug; the single retry button sits where the start button was ("Nochmal versuchen").
5. **No green/red** on this page (reserved for practice feedback in Phase 7); in-tune is shown by position.
6. Header → content gap reduced to 24px on this page so the live values and the diagnostics fit on one iPad landscape screen above the 96px free zone.
7. The app stops the mic when it goes to the background; the user taps "Mikrofon starten" again.
