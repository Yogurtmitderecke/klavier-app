# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Source legend: **[CTX D-xx]** = locked decision from 01-CONTEXT.md, **[REQ]** = REQUIREMENTS.md / ROADMAP success criteria, **[STACK]** = CLAUDE.md, **[DEFAULT]** = researcher's own choice (user did not discuss; open to review).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn) — greenfield Vite `react-ts` scaffold, plain CSS with custom properties in one `src/styles/tokens.css` (or `index.css`) [DEFAULT: Phase 1 has 3 screens; a component library is not justified] |
| Preset | not applicable |
| Component library | none — hand-written `Button`, `Tile`, `BackButton`, `WarningBar`, `VersionLabel` components [DEFAULT] |
| Icon library | none — text only; the back button uses the character `‹` (U+2039) before "Zurück" [DEFAULT] |
| Font | System font stack, no web font download (offline-friendly, fast on iPad): `-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI", system-ui, sans-serif` [DEFAULT] |
| Theme | Dark only, "Ebenholz" palette (see Color) [DEFAULT: high contrast, low glare on the music stand, a good base for later falling notes. Deliberately unlike flowkey's light/white look, UI-03] |
| Language | `<html lang="de">`, `<title>Klavier-App</title>` [REQ UI-01] |

CSS tokens must be defined once as custom properties (`--space-*`, `--font-*`, `--color-*`) and reused by all later phases. Phase 1 establishes these patterns.

## Layout & Screen Contract

Target viewport: iPad landscape (about 1180×820 CSS px, primary) and laptop browser. Portrait and narrow widths must still work but are secondary. [REQ UI-02]

### Global rules
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.
- Page padding: 32px left/right, 24px top. Add `env(safe-area-inset-*)` on top of these values.
- **Bottom free zone [CTX D-06, REQ UI-02]:** the bottom **96px** (+ `env(safe-area-inset-bottom)`) of the viewport contains **no** text, buttons, version number or notices. Only the background is visible there. Implement it as `padding-bottom: calc(96px + env(safe-area-inset-bottom))` on the app root.
- No URL or hash changes at any time. Screens switch through app state: `screen: 'welcome' | 'overview' | 'mic-placeholder'` [CTX D-03].
- Touch handling: `touch-action: manipulation` on all buttons (no double-tap-zoom delay), `-webkit-tap-highlight-color: transparent`, `user-select: none` on buttons and tiles only.
- Minimum touch target: **64px** high, **64px** wide for every tappable element [CTX discretion].
- Version label: **top-right corner** of the welcome and overview screens, 24px from the top and 32px from the right [CTX discretion: not at the bottom edge].

### Screen 1: Begrüßung (welcome) [CTX D-01, D-07]
Vertical stack, centered horizontally, laid out in the area above the bottom free zone (`justify-content: center`):
1. Display title "Klavier-App"
2. Subtitle (body, secondary text color), 16px below the title
3. 48px gap
4. *(only if `window.isSecureContext === false`)* WarningBar, max-width 720px, then a 24px gap. It sits **directly above** the Start button [CTX D-07].
5. Start button: **width 320px, height 96px**, accent fill, label "Start".

The Start button's `onClick` calls a single `onStart()` function, which currently only does `setScreen('overview')`. It is the documented hook point for the Phase 2 AudioContext and mic setup [CTX D-02]. Do NOT call `getUserMedia` in Phase 1.

### Screen 2: Übersicht (overview) [CTX D-04, D-05]
- Heading "Was möchtest du tun?" top-left at the page padding. The version label sits top-right on the same row.
- 48px below the heading: **3 tiles in one row** (CSS grid, `repeat(3, 1fr)`, gap 24px), tile **min-height 192px**, padding 24px, radius 16px.
- Below a viewport width of 720px, the tiles stack in 1 column (gap 16px, min-height 128px).
- No back button on this screen, because it is the hub. Returning to the welcome screen is not needed.

### Tile contract
| Tile | State in Phase 1 | Tap behavior |
|------|------------------|--------------|
| Mikrofon-Test | **tappable**: secondary surface, primary text, badge "kommt bald" | Opens the placeholder sub-page (Screen 3) [CTX D-05 allows this; DEFAULT: chosen to demonstrate "Zurück"] |
| Stücke üben | **greyed out**: muted surface and muted text, badge "kommt bald", `aria-disabled="true"` | Shows the inline note "Dieser Bereich kommt bald." (see Interaction) |
| Einstellungen | **greyed out** (same as above) | Same as above |

Tile content: title (heading size, weight 600) on top, a one-line description (label size, weight 400) below it with an 8px gap. The badge "kommt bald" sits in the top-right corner of the tile (label size, weight 600, pill with 4px/12px padding, neutral border).

### Screen 3: Mikrofon-Test placeholder (sub-page) [CTX D-05, D-06]
- **Back button top-left** at the page padding (24px top, 32px left): height 64px, min-width 160px, label "‹ Zurück". This position and size are fixed for **all** sub-pages in all later phases [CTX D-06].
- Page heading on the same row, 24px to the right of the back button.
- Body text 48px below the header row, max-width 720px.
- No version label on sub-pages [DEFAULT: keeps the header row clean].

### WarningBar (no HTTPS) [CTX D-07, REQ DEPL-02]
- Rendered only when `window.isSecureContext === false`. It does not block: Start keeps working.
- Full-width within max 720px, padding 24px, radius 12px, a 4px left border in the warning color, warning-surface background.
- `role="alert"`.
- The secure-address link is shown as its full URL text (so it can be read and typed), underlined, primary text color, at least 64px tall tap area (as a block element with padding).
- The URL comes from one constant (e.g. `SECURE_URL` in `src/config.ts`), not hard-coded in the component.

### Interaction states
| State | Spec |
|-------|------|
| Pressed (`:active`) on Start, tappable tile, back button | Background darkens one step (see Color), `transform: scale(0.98)`, transition 100ms ease-out |
| Focus (`:focus-visible`, laptop keyboard) | 3px outline in the accent color, 4px offset |
| Hover | Only inside `@media (hover: hover)`: same as pressed but without scale (iPad has no hover, so no sticky hover states) |
| Greyed tile tap | No navigation. The inline note "Dieser Bereich kommt bald." appears 24px below the tile row (body size, secondary text), stays 3 s, fades out. Never at the bottom edge. `aria-live="polite"` |
| Reduced motion | `@media (prefers-reduced-motion: reduce)`: no scale, no fade (show and hide instantly) |
| Screen change | Instant switch, no transition animation [DEFAULT] |

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge vertical padding |
| sm | 8px | Gap between tile title and description |
| md | 16px | Title → subtitle gap, stacked-tile gap (narrow) |
| lg | 24px | Top page padding, tile padding, tile grid gap, warning padding, warning → Start gap |
| xl | 32px | Left/right page padding |
| 2xl | 48px | Header → content gap, subtitle → Start gap |
| 3xl | 64px | Minimum touch target (height and width) |

Exceptions (all multiples of 4, all deliberate for 60 cm viewing distance and touch use):
- Start button: 320 × 96px
- Bottom free zone: 96px + `env(safe-area-inset-bottom)` [CTX D-06]
- Tile min-height: 192px (128px when stacked)
- Back button: min-width 160px, height 64px
- Content max-width (warning, sub-page body): 720px
- Badge horizontal padding: 12px
- Radii: buttons/tiles 16px, warning bar 12px, badge 999px (pill)

## Typography

Minimum body text 24px per CONTEXT ("body text ≥ about 24 px" for about 60 cm). Exactly 4 sizes and 2 weights.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 20px | 400 / 600 | 1.4 | Version label (400), tile description (400), "kommt bald" badge (600) |
| Body | 24px | 400 | 1.5 | Subtitle, warning text, sub-page body, inline "kommt bald" note |
| Heading | 32px | 600 | 1.2 | Screen headings, tile titles, Start / Zurück button labels |
| Display | 56px | 600 | 1.1 | "Klavier-App" title on the welcome screen only |

Weights: 400 (regular) and 600 (semibold) only. Never go below 20px anywhere in Phase 1. Use `font-variant-numeric: tabular-nums` for the version label. `-webkit-text-size-adjust: 100%` on `html`.

## Color

Dark "Ebenholz" palette [DEFAULT: own palette, chosen to look nothing like flowkey — UI-03]. All text pairs meet WCAG AA, and most meet AAA.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#16181D` | App background on all screens, including the bottom free zone |
| Secondary (30%) | `#252830` | Tappable tile surface, back button surface. Pressed state: `#2F333D` |
| Muted surface | `#1E2026` | Greyed-out ("kommt bald") tile surface |
| Accent (10%) | `#E8A33D` (warm amber). Pressed: `#C98A2C` | See reserved list below |
| Text primary | `#F2EFE8` | All headings, body, button labels on secondary surfaces (about 16:1 on dominant) |
| Text secondary | `#B4B0A8` | Subtitle, version label, tile description, inline note (about 9:1 on dominant) |
| Text muted | `#8C8A86` | Title and description on greyed-out tiles (≥ 4.5:1 on `#1E2026`) |
| Badge border | `#4A4E58` | "kommt bald" pill border (1px), badge text = text secondary |
| Text on accent | `#16181D` | Start button label (about 8.5:1 on accent) |
| Warning | `#E5604D` (left border 4px) on warning surface `#3A2220` | HTTPS WarningBar only. Text in the bar = text primary |
| Destructive | not used in Phase 1 (no destructive actions). Reserve `#E5604D` for destructive actions in later phases |

Accent reserved for (exclusive list):
1. Start button fill (welcome screen)
2. `:focus-visible` outline (keyboard focus on the laptop)

Nothing else uses the accent in Phase 1: not tiles, not badges, not links, not the back button. Later phases will add their own accent uses explicitly in their UI-SPEC.

## Copywriting Contract

All texts in German, informal "du" [REQ UI-01; DEFAULT for "du"]. Store the strings in one module (e.g. `src/texte.ts`) so later phases reuse the tone.

| Element | Copy |
|---------|------|
| App title (display) | Klavier-App |
| Browser tab `<title>` | Klavier-App |
| Welcome subtitle | Dein Übungsplatz am Klavier. |
| Primary CTA | **Start** [CTX D-01: locked by the user, intentionally a single word] |
| Overview heading | Was möchtest du tun? |
| Tile 1 title / description | Mikrofon-Test / Prüfen, ob die App dein Klavier hört |
| Tile 2 title / description | Stücke üben / Stücke mit fallenden Noten lernen |
| Tile 3 title / description | Einstellungen / Stimmung, Empfindlichkeit, Ansicht |
| Tile badge | kommt bald [CTX D-05] |
| Greyed tile tap note | Dieser Bereich kommt bald. |
| Back button | ‹ Zurück [CTX D-06] |
| Empty state heading (Mikrofon-Test placeholder) | Mikrofon-Test |
| Empty state body | Hier entsteht als Nächstes der Mikrofon-Test. Das Mikrofon ist noch nicht eingeschaltet. Tippe auf „Zurück“, um zur Übersicht zu gelangen. |
| Error state (no HTTPS, WarningBar) | **Achtung: Diese Seite ist nicht sicher verbunden.** Ohne sichere Verbindung (HTTPS) erlaubt der Browser kein Mikrofon – die App kann dein Klavier hier also nicht hören. Öffne die App stattdessen über diese sichere Adresse: `{SECURE_URL}` (shown as a link, e.g. `https://<benutzername>.github.io/klavier-app/`) |
| Error state (JavaScript off, `<noscript>`) | Die Klavier-App braucht JavaScript. Bitte schalte JavaScript in den Safari-Einstellungen ein und lade die Seite neu. [DEFAULT] |
| Version label | `Version {semver} · {DD.MM.YYYY} · {git-short-hash}`, e.g. `Version 0.1.0 · 22.11.2026 · a1b2c3d`. Injected at build time via Vite `define`. The hash and date guarantee a visible change on every deploy [REQ DEPL-03; DEFAULT format]. In local dev without git, the hash shows as `dev` |
| Destructive confirmation | none — Phase 1 has no destructive actions |

Typographic rules: German quotation marks „…“, a real en dash (–) as a sentence dash, no English words in visible UI.

## Accessibility & Semantics

- Buttons are real `<button>` elements. Greyed tiles stay `<button aria-disabled="true">` (focusable, so the "kommt bald" note can be announced), not `disabled`.
- Each screen has exactly one `<h1>` (welcome: "Klavier-App"; overview: "Was möchtest du tun?"; sub-page: "Mikrofon-Test").
- When the screen changes, move focus to the new screen's `<h1>` (`tabIndex={-1}`).
- WarningBar: `role="alert"`. Inline note: `aria-live="polite"`.
- Never use color as the only state signal: greyed tiles also carry the "kommt bald" text badge.

## Researcher Defaults (for user review)

These were not discussed with the user. Claude chose them within the CONTEXT "Claude's Discretion" scope:
1. Dark "Ebenholz" theme (`#16181D` background) with a warm amber accent `#E8A33D`. Light theme rejected (glare, closer to the flowkey look).
2. System font stack, no web font.
3. Type scale 20 / 24 / 32 / 56 px, weights 400 / 600.
4. Bottom free zone fixed at 96px + safe area.
5. Version format `Version 0.1.0 · DD.MM.YYYY · shorthash`, top-right corner.
6. Mikrofon-Test tile is tappable and opens a placeholder page; the other two tiles are greyed out and show an inline note.
7. Informal "du" address and the subtitle "Dein Übungsplatz am Klavier."
8. No icons and no screen-transition animations.
